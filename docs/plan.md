# План первоначальной настройки и CI

> Для агента: выполнять шаги по чекбоксам с навыком superpowers:executing-plans. Прочитать AGENTS.md и дизайн перед реализацией.

**Статус:** согласован пользователем 2026-11-10; локальная настройка выполнена. Публикация и проверка удалённого CI ожидают разрешения.

**Цель:** воспроизводимое окружение Python 3.13 и автоматическая проверка качества кода.

**Архитектура:** минимальный устанавливаемый пакет в src/reconciliation без бизнес-логики. Общие настройки и dev-зависимости в pyproject.toml, разрешённые версии в uv.lock. Локально и в GitHub Actions выполняются одинаковые проверки.

**Инструменты:** Python 3.13, uv, Ruff, mypy, pytest, GitHub Actions.

**Дизайн:** docs/design.md.

## Общие ограничения

- Python `>=3.13,<3.14`; `.python-version` — `3.13`.
- Не добавлять БД, веб-фреймворк, контейнеризацию и CD на этом этапе.
- Не писать фиктивные тесты; pytest подготовить, тестовый job пока не включать.
- Не делать коммиты и push без запроса пользователя. Git-идентичность не менять.
- Версии инструментов зафиксировать, Actions закрепить по проверенным SHA.
- Обновлять Notion и docs/STATUS.md; не утверждать, что GitHub CI прошёл, без реального запуска.

## Что проверить особенно

- Окружение действительно использует Python 3.13 — проверить версию после установки.
- Зависимости восстанавливаются без изменения lock-файла — использовать `uv sync --locked`.
- Пакет доступен из окружения, а не только из текущего каталога — проверить импорт после установки.
- CI отклоняет ошибки, а не исправляет и не подавляет их — без `--fix`, `continue-on-error` и маскировки exit code.
- Секреты и локальные выгрузки исключены из Git; workflow не требует токенов с правом записи.

## Проверка плана

План покрывает дизайн первоначального окружения и CI. Изменение бизнес-логики отсутствует, поэтому вместо новых тестов на конфигурацию используются установка, импорт, команды качества и проверка workflow. pytest начнёт запускаться с первым содержательным поведением сервиса.
