# Технические решения

## 2026-11-10: первоначальное окружение

Пользователь утвердил Python 3.13, uv, Ruff, mypy, pytest и GitHub Actions, дизайн и план настройки.

- uv управляет окружением и зависимостями. Lock-файл хранится в Git; CI отклоняет его рассогласование с pyproject.toml.
- Ruff отвечает за линтинг и форматирование, mypy — за строгую проверку типов.
- pytest запускается с появлением первого содержательного поведения, без фиктивных тестов на каркас.
- GitHub Actions проверяет Linux и Python 3.13. Другие версии и платформы пока не заявлены.
- Реализационный выбор: сохраняем установленный uv 0.8.15 и используем ту же версию в CI; backend uv_build также закреплён на 0.8.15. Это не утверждение, что версия последняя. Обновления проводим отдельным изменением с проверками.
- Работа идёт в согласованной текущей папке; локального Git-репозитория ещё нет. Коммиты и публикация требуют отдельного запроса согласно AGENTS.md. Для этого этапа изоляцию через новое рабочее дерево не создаём.

На момент первоначальной настройки модель финансовых операций, БД и веб-фреймворк ещё не были выбраны. Финансовое направление впоследствии отменено; этот раздел сохраняет историю настройки.

## 2026-11-11: FastAPI и принцип выбора технологий

**Решение пользователя:** для сайта английского для разработчиков выбираем FastAPI. Проект предназначен для обучения пользователя backend-разработке и демонстрации навыков на собеседованиях уровня middle. Приоритет при выборе стека — наиболее распространённые, мейнстримные и актуальные технологии, подходящие конкретной задаче.

**Рассмотренные подходы:** Django с серверными страницами либо FastAPI с отдельным фронтендом через JSON API. Django был предложен ради готовых механизмов пользователей, сессий и работы с БД. Пользователь предпочёл FastAPI с учётом своих учебных и карьерных целей. Сравнительный рейтинг популярности фреймворков не исследовался; решение не является утверждением о доказанном превосходстве одного фреймворка на рынке.

**Последствия:** техдизайн строим вокруг FastAPI; хранение сессий, регистрацию, доступ к БД и взаимодействие с интерфейсом описываем явно. PostgreSQL обсуждался в предложении, но отдельно ещё не утверждён; технология фронтенда и дополнительные библиотеки также не выбраны. Версию FastAPI определим при подготовке реализации. Выбор фреймворка не означает согласование полного дизайна или разрешение на установку зависимостей.

**Ограничение:** популярность инструмента не оправдывает его добавление сама по себе. Не создаём функционал ради функционала; каждое усложнение должно решать конкретную задачу. Архитектура и интерфейс остаются лаконичными, уместными и понятными пользователю.

## 2026-11-11: делегирование языковых решений

**Решение пользователя:** языковые и методические детали агент определяет самостоятельно, без согласования каждого частного случая. Это относится к согласованному первому этапу — онбордингу; полный учебный курс не добавляется автоматически.

**Определено агентом:** единица подсчёта — уникальная словоформа без учёта регистра, без лемматизации; явная разметка исключаемых фрагментов; целочисленная граница 20%; полная таблица переходов, причины и описания четырёх рекомендаций. Согласованные пять английских текстов сохранены. Нормализация, контрольные числа и тексты интерфейса записаны в docs/onboarding-content.md.

**Причины и ограничения:** правила воспроизводимы и позволяют пользователю отмечать конкретные непонятные формы. Самоотметка слов не проверяет понимание текста или уровень CEFR; порог и порядок сложности остаются гипотезами до проверки с аудиторией. Оба исхода уточняющего текста ведут к «Основам», но сохраняют разные причины результата. Это следствие четырёх согласованных рекомендаций, а не забытая ветвь алгоритма.

**Технический статус:** подготовленный docs/design.md предлагает оставшийся стек, API, хранение, регистрацию, обработку сбоев и критерии приёмки. FastAPI уже выбран пользователем; остальные существенные технические решения в документе ещё ожидают общего согласования. План и реализация не объявляются готовыми.

## 2026-11-11: утверждение технического дизайна онбординга

Пользователь подтвердил утверждение docs/design.md целиком и поручил подготовить пошаговый план. Эта запись заменяет прежние отметки об ожидании общего согласования, сохраняя историю обсуждения.

Приняты PostgreSQL, синхронные SQLAlchemy 2/psycopg 3, Alembic; React/TypeScript/Vite; серверные cookie-сессии; логин/пароль с Argon2 без восстановления на первом этапе. Срок сессий 7 суток, очистка не привязанных результатов через 30 дней после истечения. Один HTTPS-origin, транзакционное хранение и версионирование контента. Причины, альтернативы и ограничения — в дизайне.

Конкретный хост, домен и бюджет остаются открытыми. Подготовленный docs/plan.md — предложение для отдельного согласования; установки зависимостей, реализации, коммитов и публикации это решение не разрешает.

## 2026-11-11: план согласован и реализованы чистые правила

Пользователь согласовал порядок всех 10 шагов и формат «один проверяемый шаг → краткий разбор». Обычные правки разрешены; коммиты, push и публичное размещение по-прежнему требуют соответствующего запроса.

Задача 1 реализована на стандартной библиотеке Python, без новых зависимостей: frozen dataclass и tuple для неизменяемых снимков, явные словари word_id в JSON, отдельные версии нормализации и маршрутизации. Проверка нормализует английскую словоформу, но не исходное отображение. SHA-256 считается по UTF-8 JSON с sort_keys и компактными разделителями; форматирование объектов не влияет, порядок массивов значим.

Порог сравнивается целыми числами, без округления. Функции не знают о HTTP и БД; следующий шаг добавит транзакционное хранение, не перепишет правила. Пакет routing-v1 проверяется по утверждённым переходам: смена смысла маршрутов потребует новой версии политики и поддержки в коде. Доменоподобные фрагменты и записи, похожие на вызовы функций, отклоняются без явной разметки; произвольный английский и код автоматически не распознаются.

Проверки: 176 unit-тестов, Ruff lint/format, mypy и демонстрация README прошли локально. CI дополнен unit-тестами, но новый workflow удалённо не запускался. Это проверка правил, не API, сохранения прогресса или эффективности обучения.
