# Тренажёр рабочих ситуаций

`/trainer` открывается по ссылке «Тренажёр» в навигации или «Открыть тренажёр»
под основным действием на главной. Подбор сложности и аккаунт для него не нужны.
Четыре темы содержат по три авторских задания. В каждом нужно прочитать ситуацию,
выбрать ответ и нажать «Проверить ответ». После проверки доступны объяснения всех
вариантов на русском. Метки A2/B1 — авторский ориентир сложности, не сертификация.

## Как это устроено

Путь данных: JSON в Git → Pydantic → CLI → PostgreSQL → FastAPI → React.

- `content/trainer-v1.json`: версия схемы, версия пакета, четыре темы. У задания
  стабильный ID, заголовок, уровень, английские ситуация и вопрос, 3–4 варианта.
  Каждый вариант содержит ID, текст и объяснение; `correct_option_id` указывает лучший.
- `trainer/content.py`: неизменяемые Pydantic-модели. Проверяются размеры пакета,
  допустимые темы/уровни, уникальность ID заданий и вариантов, непустые тексты,
  наличие правильного варианта и отсутствие лишних полей. SHA-256 считается по
  каноническому JSON: порядок ключей и форматирование не влияют, порядок массивов влияет.
- `trainer/importer.py`: импорт внутри транзакции вызывающего кода. Повтор версии
  с тем же содержимым безопасен; другое содержимое под тем же именем запрещено.
  Для исправления текста публикуется новая версия. `ON CONFLICT` сериализует
  конкурирующую вставку одной версии. Настройка активной версии меняется атомарно.
- `storage/models.py`: `trainer_bundles(version PK, content_hash, content_json JSONB,
  created_at)` и `trainer_settings(id=1, active_version FK)`. Старые версии остаются.
  У тренажёра нет таблицы пользователей или ответов.
- `GET /api/v1/trainer`: публичный endpoint без сессии и CSRF. Одним SQL-запросом
  читает активный пакет и возвращает `{content_hash, content: {schema_version,
  version, topics}}`. Ответ включает правильные варианты и объяснения. Если пакет
  ещё не активирован — 503 `trainer_unavailable`; при отказе БД — 503. Проверка
  ответа выполняется в браузере: это самостоятельная практика, не экзамен.
- `frontend/src/main.tsx`: выбирает тренажёр по пути `/trainer`; остальные пути
  обрабатываются прежним `App`. `trainer/Trainer.tsx` отвечает за загрузку/retry,
  выбор темы и итог; `Question.tsx` — выбор ответа и объяснения. `types.ts` описывает API, `progress.ts` — storage,
  `trainer.css` — стили, ограниченные классом `.trainer`.

## Прогресс

Ключ localStorage — `english-for-developers:trainer:v1:<content_hash>`, значение —
словарь `{exercise_id: option_id}`. Счётчики вычисляются по нему, поэтому повторный
ответ заменяет предыдущий, а не увеличивает число пройденных заданий. Незаконченная
тема открывается с первого неотвеченного задания; законченная — с первого для повторения.
Перезагрузка открывает каталог с сохранёнными счётчиками. Непроверенный выбор не сохраняется.

Новая редакция контента получает отдельный прогресс; старые записи автоматически
не удаляются. Повреждённые записи и неизвестные ID игнорируются. При запрете записи
или переполнении storage показывается сообщение, практика работает в памяти до
перезагрузки. Событие `storage` обновляет другие вкладки; перед записью подмешиваются
их последние ответы. localStorage не обеспечивает атомарность одновременных записей
в двух вкладках. Прогресс не переносится между устройствами и не связан с аккаунтом.

Радиокнопки и кнопки нативные, вопрос размечен через fieldset/legend. При переходах
фокус ставится на заголовок, при проверке — на текстовый вердикт; правильность
обозначена словами и символом ✓. Английские фрагменты имеют `lang="en"`.

## Почему так

Отдельные таблицы позволяют выпускать тренажёр независимо от контракта онбординга.
JSONB соответствует существующему импорту: пакет мал, нормализация каждой опции
в отдельную таблицу пока усложнила бы публикацию. Один GET отдаёт все 12 заданий:
меньше состояний загрузки, версия не меняется посередине темы. Постраничное API
может понадобиться при росте каталога. Чтение JSON с диска вместо импорта было бы
проще, но не давало бы явного выбора активной версии в БД. Серверные ответы и
проверка потребовали бы хранения сессии, которое для текущей практики не нужно.

## Запуск и проверка

После настройки отдельной БД и установки зависимостей по README:

```bash
uv run --locked alembic upgrade head
uv run --locked python -m english_for_developers.cli trainer validate content/trainer-v1.json
uv run --locked python -m english_for_developers.cli trainer import content/trainer-v1.json --activate
```

`./dev.sh` импортирует оба пакета. В production существующий one-shot сервис
`import-content` последовательно импортирует онбординг и тренажёр. Эти две публикации
имеют независимые транзакции: при сбое второго импорта команда завершается ошибкой,
первый уже сохранён; повтор команды безопасен. Старт backend не выполняет импорт.
Миграция `0004_trainer` добавляет только две таблицы; предыдущий код продолжает
работать. `alembic downgrade 0003_telegram_identities` удаляет только контент тренажёра,
который можно заново импортировать после upgrade. Прогресс браузера при этом остаётся.

Проверки: команды README; полный Python-набор — `uv run --locked pytest tests -q`
с обоими URL на disposable БД `*_test`. Playwright — `cd frontend && npm run test:e2e`;
перед ним заново импортировать **оба** пакета в тестовую БД после pytest.
CI теперь запускает также `tests/api` и импортирует тренажёр перед E2E.

Ручной сценарий:

1. Открыть главную, перейти в тренажёр; проверить четыре темы и нулевые счётчики.
2. В Code review выбрать неправильный ответ. До проверки объяснений нет;
   после проверки видны ваш ответ, лучший вариант и объяснения всех трёх вариантов.
3. Вернуться к темам: пройдено 1/3, правильно 0/3. Перезагрузить — счётчики сохранены.
4. Продолжить тему: откроется второе задание. Закончить тему, повторить первое
   с верным ответом: правильно станет 3/3, пройдено останется 3/3.
5. Пройти остальные темы; повторить действия на ширине 375 px и клавиатурой
   (Tab, стрелки в группе вариантов, Space/Enter). Фокус следует за экраном/вердиктом.
6. Проверить онбординг, вход и регистрацию прежним сценарием; тренажёр доступен
   и гостю, и вошедшему пользователю, его ответы не создают прохождений онбординга.
