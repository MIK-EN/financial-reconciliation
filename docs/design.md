# Первоначальная настройка и CI

Статус: согласован пользователем 2026-11-10. Дизайн самого сервиса будет добавлен после уточнения предметных требований.

## Цель

Получить воспроизводимое окружение Python 3.13 и одинаковые локальные и автоматические проверки до разработки бизнес-логики.

## Выбранный подход

Пользователь согласовал uv, Ruff, mypy, pytest и GitHub Actions.

Рассматривали venv + pip: это работоспособный вариант, но создание окружения и фиксация полного набора зависимостей требуют отдельных соглашений. Выбран uv, объединяющий эти операции и работу с lock-файлом.

## Предлагаемое устройство

- `pyproject.toml`: метаданные, ограничение Python `>=3.13,<3.14`, группа зависимостей разработки и настройки инструментов.
- `.python-version`: ветка Python 3.13; исправления безопасности в пределах 3.13 разрешены.
- `uv.lock`: зафиксированные зависимости, хранится в Git. В CI установка с `uv sync --locked`; рассогласование с описанием зависимостей — ошибка.
- `src/reconciliation/`: минимальный пакет без бизнес-логики. Разделение на модули определим после требований.
- Ruff: линтинг и проверка форматирования. В CI исправления автоматически не применяются.
- mypy: строгая проверка пакета с начала разработки; исключения добавляются адресно с объяснением.
- pytest: инструмент подготовлен, но запуск тестов подключается вместе с первым содержательным тестируемым поведением. Отсутствие тестов пока обозначаем явно; фиктивные тесты и подавление ошибок pytest не используем.
- `.gitignore`: окружения, кеши, секреты, локальные выгрузки и результаты обработки не попадают в Git.
- `README.md`: назначение, установка и команды проверок, текущее ограничение — приложения и тестов ещё нет.

## CI

Один workflow в `.github/workflows/ci.yml`: Linux, Python 3.13, запуск на push и pull request. Зависимости устанавливаются из lock-файла, затем последовательно проверяются линтинг, форматирование и типы. Ошибка любого шага завершает job неуспешно.

Доступ workflow — чтение содержимого репозитория. Секреты на данном этапе не нужны. Используем обычный `pull_request`, а не выполнение кода внешнего PR в привилегированном контексте. Версии uv и используемых Actions фиксируем при реализации; Actions закрепляем по SHA с поясняющим тегом.

Проверки локально и в CI используют одни и те же команды. Базу данных, контейнеризацию, веб-фреймворк и CD этот этап не выбирает и не добавляет.

## Критерии готовности

1. Окружение восстанавливается из файлов проекта на Python 3.13.
2. Lock-файл актуален, линтинг, форматирование и типы проходят локально.
3. README содержит воспроизводимые команды и честно описывает отсутствие тестов и приложения.
4. Workflow настроен на те же проверки. Успех на GitHub подтверждаем только после реального запуска.
5. Notion и `docs/STATUS.md` обновлены с результатами и ограничениями.

Создание коммита и публикация локальных файлов не входят в разрешение автоматически: по AGENTS.md для них нужен запрос пользователя. До публикации workflow можно проверить локально, но нельзя утверждать, что CI уже прошёл на GitHub.
